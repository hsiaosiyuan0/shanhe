# 山河 v0.1 产品与工程设计

本地 Codex 已支持流式对话、故事工具和会话续接，详见 [LOCAL_AGENTS.md](LOCAL_AGENTS.md)。

## 产品模型

Story 是一次可以持续编辑的地理叙事，而不是一次性生成的网页。一个 Story 包含事件、地点标记、路线、图层、视角、对话及版本记录。

事件把「什么时候、发生什么、在哪里、为什么值得注意」连接起来。选中事件时，时间线、地图位置、事件卡片同步变化。人物生平与王朝历史共用事件模型；旅行故事暂以第几天代替年份。

地点标记独立于事件。山脉、河流、古迹和临时笔记都可以作为辅助图层存在，不必虚构一条历史事件。路线也是独立对象，可以由模型新增多条路线，给不同的观察方式留下空间。

历史行程与人生事件必须分开。出生地、登第地、任职地不构成连续旅行：两次任职之间可能有返乡、服丧和多次往返。`route.journey` 为兼容旧数据的可选结构，包含起止年份、关联事件 ID、地点索引与依据、连续分段的交通方式（陆/水/未定）、证据状态、说明及来源。坐标只表达当前资料的精度，界面明确称为走廊。分段须覆盖整条路线；未知部分显式标记，禁止省略后偷偷连线。资料提及地点不等于证实两点之间的道路。

地图的「行程」阅读视图只展示所选行程，可切换行程、定位分段、查阅地点依据。退出行程或选择其他年代时收起其走廊。历史故事的 `layers.connections` 默认关闭；显式打开后才显示旧的地点关系曲线。旅行故事的旧路线仍表示规划示意。独立行程使用原始坐标与分段，不做样条平滑，不从事件索引推算进度。

## 模型可以使用的能力

对外暴露一个 `apply_story_actions` 批处理工具，内部由五种受校验的动作组成。

| 动作         | 数据                                                         | 用户看见的结果             |
| ------------ | ------------------------------------------------------------ | -------------------------- |
| `add_event`  | 年份、标题、地点、坐标、描述、类别                           | 新时间节点和对应地图标记   |
| `add_marker` | 名称、坐标、类型、说明                                       | 可点击的地点笔记           |
| `add_route`  | 有序坐标、名称、颜色、可选 journey 行程信息                  | 地点关系或可查阅的分段行程 |
| `set_view`   | 中心、缩放、倾角                                             | 地图转到当前讨论区域       |
| `set_layers` | 海拔设色、现代省界、三维地形、河流、地貌、行程及地点连线开关 | 改变地理信息呈现           |

`GET /api/capabilities` 返回实际 JSON Schema，可供其他本地 Agent 读取。Zod schema 同时约束 HTTP 请求、导入文件与模型输出。坐标采用 `[经度, 纬度]`，不使用容易混淆的 `[纬度, 经度]`。

v0.1 的模型不能执行任意代码、SQL、文件读写、网络检索或删除故事。修改经过校验后暂存在内存，工具结果交回模型，模型给出最终回答后，再把整轮数据放进一个 SQLite 事务。模型服务失败、中途出错、轮次超限时，本轮不落库。每轮最多五次模型请求、40 个动作，总请求时间上限 90 秒。

新增史实与来源应有单独的核验流程。目前没有搜索工具，因此不会把模型输出宣称为已查证事实，模型提供的来源 URL 也不会直接挂到事件上。

模型新增行程在服务端强制设为 `unverified`，移除来源链接、将地点及分段证据降为 `unknown`。可信来源不能靠模型自填字段获得；现有研究行程仅来自人工整理的示例资料或用户自己的导入。真实模型新增行程后会打开其阅读面板。当前没有自动古道检索、文献核验或古代路网寻径。

## 后端与持久化

React 通过 HTTP JSON API 与后端通信；聊天支持 SSE 流式事件。地图渲染和数据库逻辑完全分开。开发时 Vite 将 `/api` 代理到独立端口；生产 Web 版与 macOS 桌面版由 API 进程额外提供静态文件，仍使用同一套清晰的接口边界。

SQLite 开启 WAL、外键与 busy timeout。数据表：

| 表          | 用途                                 |
| ----------- | ------------------------------------ |
| `stories`   | Story JSON 文档、单调递增的 revision |
| `messages`  | 每条聊天消息及工具操作回执           |
| `snapshots` | Story、视角、聊天的版本快照          |
| `settings`  | 本机模型地址、名称与密钥             |
| `metadata`  | 数据初始化状态                       |
| `agent_sessions` | 故事与本地 Codex 会话的关联、连接指纹与 revision |
| `chat_locks` | 跨连接的故事对话锁与过期续租 |

初版采用文档聚合存储，便于模型生成、导入/导出和快照。以后如果需要跨故事全文检索或上万事件，增加 SQLite FTS5 / 索引表即可，不需要引入另一套数据库。

每次更新携带 `revision`，更新语句只有在旧版本匹配时才成功，否则返回 409。服务端还限制同一故事同时只有一轮模型请求。手动编辑在模型回答前发生时，会导致那轮模型结果因版本冲突而放弃，避免丢失较新的操作。

恢复快照会在同一事务中自动备份当前内容、更新 Story、恢复聊天，并递增 revision。导入生成新的 Story ID 和消息 ID，不覆盖原始故事。

1056 年示例升级只匹配旧 `su-route` 的完整坐标指纹，保留原节点与路线，并新增出发事件及独立行程。修改过坐标或存在冲突 ID 时跳过；自定义路线名称保留。升级前自动快照，`metadata` 按故事记录迁移完成，恢复旧快照后不会在重启时重复升级。没有全量替换用户的故事库。

## 主要 HTTP 接口

| 接口                                                | 用途                            |
| --------------------------------------------------- | ------------------------------- |
| `GET/POST /api/stories`                             | 列表、创建                      |
| `GET/PUT/DELETE /api/stories/:id`                   | 读取完整故事、更新、删除        |
| `POST /api/stories/:id/actions`                     | 校验并应用地图操作              |
| `POST /api/stories/:id/chat`                        | 模型/演示指令，返回完整最新状态 |
| `POST /api/stories/:id/snapshots`                   | 保存快照                        |
| `POST /api/stories/:id/snapshots/:snapshot/restore` | 恢复版本                        |
| `GET /api/stories/:id/export`                       | 导出可迁移 JSON                 |
| `POST /api/import`                                  | 导入一个新故事                  |
| `GET/PUT /api/settings`                             | 模型设置，GET 不含密钥          |
| `GET /api/capabilities`                             | 模型操作的 JSON Schema          |

## 本地 App

macOS 原生外壳由 Swift / AppKit / WKWebView 实现，负责打开工作台、管理独立 API 子进程、打开外部参考链接，以及系统文件导入/导出面板。网页使用 WebKit 的独立内容进程，不提供原生脚本桥接。打包时复制本机 Node 运行时与生产依赖，API 绑定随机 loopback 端口，数据落到 Application Support/山河，不要求用户安装数据库或常驻服务。

浏览器模式固定使用 4310/5178。服务验证 Host/Origin、限制 JSON 请求体大小、阻止远程明文 HTTP 模型地址（loopback 例外），静态页面拿不到数据库凭据。当前按单机单用户设计；若日后支持局域网，必须先增加身份认证，不能直接把监听地址改成 `0.0.0.0`。

## 接下来最有价值的三步

1. **历史地理图层**：引入带有效时间区间、出处、精度说明的历史行政区 GeoJSON。让 timeline 的当前年份控制图层版本，区分历史疆界、历史河道、现代参照；需要先明确授权与资料来源。
2. **带来源的研究工具**：增加检索、地名消歧、出处摘录、待审草稿。让模型先提出变更与证据，用户可逐项采纳；保留当前直接编辑的小范围操作体验。
3. **持续编辑能力**：增加资料面板、事件/路线删除与重排、路线点编辑、对话断点恢复、离线地形缓存和桌面签名发布。

这些能力都可以在当前模型、接口和 SQLite 上扩展。
