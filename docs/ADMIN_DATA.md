# 现代行政区数据

[← 地图数据与精度](GEOGRAPHY.md)

山河的省、市、区县对照统一使用用户从[天地图 · 行政区划](https://cloudcenter.tianditu.gov.cn/administrativeDivision/)下载的三个全国 GeoJSON 文件。网页标注 **2025 年 9 月更新**，下载于 **2026-09-08**，用途说明为 **「该数据仅供地图可视化使用」**。来源页面展示的审图号为 GS（2024）0650号；这是来源页面的标识，不表示山河的组合地图经过同一审查。

## 原始文件与覆盖

| 下载文件 | 行政区面要素 | 独立「境界线」要素 | 原始字节数 |
| --- | ---: | ---: | ---: |
| 中国_省.geojson | 34 | 8 | 1,698,398 |
| 中国_市.geojson | 375 | 13 | 4,265,699 |
| 中国_县.geojson | 2,891 | 7 | 10,006,881 |

数量是文件中的要素数，不据此推断法定行政单位总数。直辖市、县级市等名称与代码均沿用文件的分组；县级市也出现在区县层。面要素使用原始 `gb` 代码作为 ID，名称使用原始 `name`。

原文件以 gzip 无损归档在 [`public/data/admin/source/`](../public/data/admin/source/)，解压后的内容与下载文件逐字节一致。[manifest.json](../public/data/admin/manifest.json) 记录原文件、渲染包的 SHA-256、体积、数量与来源信息，应用加载时校验渲染包的哈希值。失败时提示重试，不退回另一来源的边界。

渲染包另提供 `.topo.json.gz`，浏览器优先下载并无损解压，再校验原始 TopoJSON 的 SHA-256，避免静态托管未压缩 JSON 时下载过慢。不支持 `DecompressionStream` 的浏览器继续使用原始 JSON。

## 坐标与精度

三个原文件均显式标注 **CGCS2000 / EPSG:4490**。应用保留原始经纬度，在区域尺度的 Web 地图上按地理经纬度近似显示，**未施加 GCJ-02 偏移，也没有声称完成精确的 CGCS2000 → WGS84 坐标转换**。故事点和其他底图使用其各自文档说明的坐标参考。

这是现代区划的可视化数据包，边界本身经过概括，放大后有折线，不能代替详细界址、测绘成果或历史疆界。我们没有对边界做取整、量化、平滑、吸附、补线或删小岛。标签锚点通过 polylabel 选在区域最大组成面的内部，只用于排版，不能解释为政府驻地。

## 绘制与悬停

- 默认「随缩放」：小于 6 显示省级，6 到 9 显示市级，9 及以上显示区县。市级覆盖更宽的缩放范围，避免稍微放大就丢失市名。
- 点击「省界 / 市界 / 区县界」会固定显示该层级，保留当前视角，后续缩放、平移不会自动切换；点「随缩放」恢复自动模式。这个选择属于当前故事页面的浏览状态，不修改故事数据，切换故事或刷新后回到自动模式。
- 同一时刻只有一个行政区层级的边界；线宽统一。加载新层级时隐藏上一层，避免把不同精度的省、市、县边界同时叠画。
- TopoJSON 保留原始多边形及其共享弧段；`mesh` 将同级共享边界只绘制一次。高亮直接使用同一个包解码出的原始多边形，包含内洞和离散组成面。
- 「境界线」是原文件中的独立 MultiLineString，原样保留并单独绘制，不将其闭合为面或用于行政区命中判断。
- 悬停直接在本地多边形上命中，不依赖 Overpass，也不等待在线地形加载完成。离开地图、拖动、切换层级或关闭对照会清理高亮。
- 桌面版随包提供全部三个层级；网页版从同站点按层级加载静态文件并在会话内缓存，不向第三方发送鼠标位置。网页版首次取得文件仍需要网络。
- 11 级以后保留 OSM / OpenFreeMap 的乡镇、街区地名补充。这一在线来源**只提供地名，不参与行政区边界或悬停**，不影响本地省市县数据可用性。

现代区划由原有 `layers.admin` 开关控制，不写入用户故事，不随时间线年份改变。模型可通过 `set_layers` 和 `set_view` 控制显示；本次未增加精确行政归属查询工具。

## 检查结果与已知源数据问题

[`audit.json`](../public/data/admin/audit.json) 使用 Shapely 2.1.2 检查三个原始包。所有面要素均通过几何有效性检查；这不等于所有界址已由我们核定。

用户截图中的 **高淳区与郎溪县**：面积交集为 0，共享边界长度约 0.182596952 度；原数据中有 7 段完全相同的公共边界线段。宣州区保留一个内洞，未按视觉判断删除任何小块。

全国相邻面检查发现以下原始数据交叠，阈值为 `1e-10` 平方度。平方度用于几何诊断，不是面积测量单位，不能直接当作平方米：

| 层级 | 相交区域 | 交叠面积（平方度） |
| --- | --- | ---: |
| 省 | 江苏省 / 山东省 | 2.6501042000028647e-5 |
| 市 | 日照市 / 连云港市 | 2.6501042000028647e-5 |
| 县 | 岚山区 / 连云区 | 2.6501042000028647e-5 |
| 县 | 南票区 / 太和区 | 8.237004010517488e-8 |
| 县 | 大洼区 / 兴隆台区 | 1.4628233787654312e-9 |
| 县 | 大洼区 / 盘山县 | 1.275676533214633e-9 |
| 县 | 千山区 / 铁东区 | 1.7950002170313318e-10 |

前三项是跨层级出现的同一位置问题。应用保留源数据，没有擅自裁切；若鼠标位于这些交叠处，当前命中结果取文件中先出现的区域，不能据此判断行政归属。审计没有验证省、市、县之间的法定隶属，也没有核验数据包之外的缺失区域。

## 复现与更新

```sh
# 已安装 npm 依赖，并把三个下载文件放在同一目录
npm run data:admin -- /path/to/downloads
npm test
```

构建使用不量化的 `topojson-server`；原始代码、名称、组成面、内洞、境界线均保留。测试逐区域检查每个环的原始线段与解码结果一致，验证公共边界不重复、没有新增连接线，以及所有标签落在对应区域内。

构建脚本固定核对本次原文件的哈希，避免新下载内容被误标为旧版本。更新数据时需先核验新来源页面、坐标系、文件差异，再更新脚本的版本和哈希，重建三个层级并运行审计。

完整空间审计是可选的开发检查，Python 包不参与应用运行或 macOS 打包：

```sh
python3 -m venv /tmp/shanhe-admin-audit
/tmp/shanhe-admin-audit/bin/pip install shapely==2.1.2
/tmp/shanhe-admin-audit/bin/python scripts/audit-admin-package.py > public/data/admin/audit.json
```
